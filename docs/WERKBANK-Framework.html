01 · Standortbestimmung — gegen das Profi-Umfeld

Wo das Feld steht. Wo Werkbank steht.

Spec-Driven Development (SDD) ist 2026 das dominierende Paradigma: die Spezifikation ist die Quelle der Wahrheit, Code ist generierter Output. Der entscheidende Reifegrad-Sprung des letzten Jahres ist nicht „mehr Agenten" — es ist die Spec als ausführbares Validierungs-Gate statt als totes Dokument.

A

Spec = Vertrag

Die arXiv-Arbeit „From Code to Contract" (Feb 2026) bringt es auf den Punkt: klassische Specs liest ein Mensch — SDD-Specs laufen als Gates. Sie fangen Architektur- und Vertragsverstöße ab, die Unit-Tests strukturell nicht sehen.

B

Living statt Static

Die Spitze (Intent/Cosmos) hält Spec ↔ Code bidirektional synchron. Statische Specs (BMAD, Spec Kit) driften „innerhalb von Stunden". Werkbank schließt das per Drift-Audit-Gate — ohne den US-Cloud-Zwang dieser Tools.

C

Coordinator·Implementor·Verifier

Das produktive Muster: ein Koordinator zerlegt, mehrere Implementoren bauen parallel in isolierten Worktrees, ein Verifier prüft — über einer geteilten Memory-Schicht. Genau deine Topologie: Junge · Dev · Wächter · MCP.

04 · Die Spec als Vertrag

Sechs Felder. Sonst keine Freigabe.

Eine produktionstaugliche Spec ist kein Fließtext, sondern ein schema-validiertes Artefakt mit Pflichtfeldern. Fehlt eines, blockiert Gate A1 — so können spätere Agenten nichts hineininterpretieren, was nie spezifiziert wurde.

1

Outcomes

Was am Ende wahr sein muss — beobachtbar, nicht vage.

2

Scope-Grenzen

Was ausdrücklich nicht dazugehört.

3

Constraints

Technik, Recht, DSGVO, Branchenregel — als harte Leitplanke.

4

Prior Decisions

Frühere Entscheidungen + Begründung (ADR), gegen Drift.

5

Task-Breakdown

Stories mit Done-Kriterien, einzeln testbar.

6

Verification

Akzeptanzkriterien, die als Gate ausführbar sind.

Living-Spec-Mechanik

Nach jeder Story difft das Drift-Audit-Gate (H6) die Implementierung gegen die Spec und meldet nur das, was eine beabsichtigte Verhaltensänderung ist — nicht jede Zeile. Beabsichtigt → Spec wird versioniert nachgezogen. Unbeabsichtigt → Finding. So bekommst du living-spec-Verhalten, ohne den Token-Overhead einer permanenten Vollsynchronisation.

05 · Quality-Gates — der Härtungs-Layer

62 Gates. Erst billig, dann klug.

LLMs erzeugen verwundbaren Code in 9,8 – 42,1 % der Fälle. Genau dagegen ist dieser Layer gebaut. Das Designprinzip senkt zugleich die Kosten: deterministische Tools laufen zuerst (kein Token) — das LLM-Urteil trifft nur, was bereits durchgekommen ist.

06 · Der Übergabe-Vertrag

Was „übergabefertig" konkret bedeutet.

Ein Entwickler übernimmt kein Black-Box-Artefakt, sondern ein vollständiges, prüfbares Bündel — mit dokumentiertem Intent, nicht nur Ist-Code. Reverse Engineering entfällt.
